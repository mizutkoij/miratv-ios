# MiraTV — status snapshot (2026-10-19)

iPhone app (SwiftUI + FFmpegKit) to watch Mirakurun TV, radio, EPG, recordings, data broadcast, captions, PiP.
Built on GitHub Actions (`macos-15`, XcodeGen + SwiftPM FFmpegKit), installed with iLoader (Windows, anisette
`Jkcoxson (Windows)`). Free Apple ID signature lasts 7 days: **expires 2026-10-22, reinstall before then.**
Latest device-tested build: ci27. Latest code: ci28 (edits applied, **not built yet**).

## 2. Data broadcast: how it works and the lessons

Server: Docker container `web-bml` on homeserver `:23234` (Tailscale only). Page: `startup.bml` (invisible launcher) ->
press `d` (`#key20`) -> `top2.bml` visible. Everything renders in a closed Shadow DOM (we patch `attachShadow` to keep roots).

Final design (ci27):
- `video{visibility:hidden}` (NOT `display:none`: the box must keep its layout rect). The real video is drawn natively
  on top of the WebView, in the BML video box.
- The page reports the box as **fractions of the BML `html` element** (not CSS px; innerWidth 1102 != view points,
  html is rescaled to 1512 after web-bml resize). Swift multiplies by the container size via `GeometryReader`.
- Reporter every 250 ms; heavy DOM description every 2 s. Last box is kept 1.2 s when it vanishes (page change), 0.2 s animation.
- `d` is a toggle. Auto-press only while BML logs `invisible true` and the indicator shows a `startup.bml`;
  retry every >3 s (cap 12). Reasons: pressing while visible closes it (ci21 loop, ci24 white on page change);
  pressing before the launcher data is ready is ignored (ci25 stuck white).
- `ready` = indicator contains `.bml` AND something is actually drawn.

Known limits: BML popups overlapping the video box are covered by the native video; captions align to the full
frame, not the box; PiP/captions for recordings in data mode untested; gzip for `arib.js` disabled
(`dist/arib.js.gz.off`, route patch backup `index.js.bak-gzip`).

## 3. Server side (homeserver)

- `miratv-chapterd` (user systemd): `~/miratv-chapterd/chapterd.py`, port 23235, Tailscale bound. Endpoints:
  `GET /chapters/<id>?name=`, `GET /health`, `POST /log`, `POST /shot`, **`GET|HEAD /raw?name=` (new, deployed 2026-10-19)**.
- `/raw` serves a recording file with HTTP Range, bare file names only (no path parts), `.ts/.m2ts/.mp4/.mkv`,
  searched up to 3 levels under `/home/homeserver/recorded`. Verified: 206 with correct `Content-Range`, traversal returns 404.
- `web-bml` container `:23234`. Keep both Tailscale-only.

## 4. Decision in progress: play recordings without EPGStation (2026-10-19)

User intent: recorded TS should be playable directly; going through EPGStation (Node) is heavy.
- Done: `/raw` endpoint (server), `ChapterClient.rawURL/rawAvailable` (HEAD check), `RecordedPlayerView.start()` uses the
  direct URL for TS and falls back to EPGStation when unavailable (logs `[rec]`). **ci28 not built/tested yet.**
- Still EPGStation: the recording list, metadata, reservations/rules (only the video bytes bypass it).
- Open: user reports "TS playback has problems" — symptoms not yet given (ask: what shows / when). Possible follow-ups:
  captions/data for mp4 (needs original TS), badges for captions/data in the list.
