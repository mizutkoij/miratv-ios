# ci65: 録画中の録画を、いま録っているところまで追いかける（2026-10-21）

これまで、録画中の番組を開くと「開いた時点のファイルの長さ」までしか読めず、その先にはシークできず、端まで来ると止まっていた。

## 使い方
- 録画一覧で「● 録画中」の番組を開くと、自動でこの方式になる
- シークバーは「いま録れているところ」まで。5 秒おきに伸びる
- 「追う」: 押すたびに ×1.5 → ×2 → 等速。いま録っているところの 5 秒手前まで来たら等速に戻る
- 「-12:34 / LIVE」: いま録っているところまでの遅れ。押すとそこへ飛ぶ（15 秒以内なら LIVE）
- そのまま見続けると、録画の端を追いかけて流れ続ける。録画が終わったら、自動で普通の録画の再生に切り替わる（位置はそのまま）
- CM 検出・字幕で探すは、録画が終わってから

## サーバー（homeserver の chapterd）
- `server/follow.py` を chapterd.py と同じフォルダに置いて再起動
- `GET /follow/info?name=` → いま録れている長さ（秒）・大きさ・まだ書き足されているか
- `GET /follow?name=&t=秒` → その時刻から流し、書き足される分も流し続ける。20 秒書き足されなければ終わり。待っている間も 2 秒おきに空のパケットを送って接続を保つ
- 時刻は TS の PCR（放送の時計）から出すので、録画が終わったあとの位置と同じ。位置からバイトへの換算は二分探索（小さな読み込み 20 回ほど）
- エンコードはしない。ファイルを読んで流すだけ

## 中身
- PlayerEngine: 「流し直してもらう」方式のシーク（`playFollowing`）。位置・長さ・シークは録画と同じ API のまま使える
- RecordedPlayerView: 録画中なら chapterd の /follow で開く。古い chapterd（/follow が無い）ならこれまでどおり

## レビューで直したもの
- 録画が終わった瞬間、最後の数秒をくり返し再生し続けることがあった → 録画が続いているかを 5 秒おきに確かめ、終わっていれば普通の再生へ。もう一度流し直すのは、10 秒ちゃんと流れたあとだけ
- 待っている間（いま録っているところに追いついた状態）に、プレイヤーが読み切れで止めていた → サーバーが 2 秒おきに空のパケットを送る
- 端の近くで見ていると「続きから」の位置が消えていた → 録画中は番組の長さで判断
- 開いてすぐ閉じたのに、裏で再生が始まることがあった
- 録画中の録画で、直接配信が使えないときに EPGStation 経由へ切り替わらなくなっていた
- 端の近くで +30 秒・LIVE を押すと少し後ろに戻ることがあった
- サーバー: 録れている長さを末尾の小さな範囲から正しく出す（1 秒ほど短く出ていた・最大 40MB 読んでいた）。黙って切れた端末の接続を残さない
