# ci46: 追っかけ再生（2026-10-19）

ライブを止めたり戻したりして見られるようにした。streamd が見ている局の直近の放送を homeserver のディスクに貯める（エンコードしないので CPU はほぼ使わない）。

## 使い方
- 原画質で見ていると、映像の下（横画面では下のバーの上）に操作が出る
  - ⏪15: 15 秒戻る
  - 一時停止: その場で止める。再生で止めたところから続き
  - シークバー: 貯まっている範囲（既定で最大 30 分前まで）をドラッグ
  - LIVE / -1:23: ライブより何秒遅れているか。押すとライブに戻る
- ロック画面の一時停止も、追っかけが使えるときは「その場で止めて後で続き」になる
- 実況コメントは追っかけ中もリアルタイムのまま（過去ログとの同期はこの先）
- 設定 › 「追っかけ再生」でオフにできる（オフなら streamd に貯めさせない）

## サーバー（homeserver）
- streamd.py を入れ替えて再起動。`TIMESHIFT_DIR` と `TIMESHIFT_MINUTES` は miratv-streamd.service で変えられる（docs/streamd.md）
- 30 分で約 4GB のディスクを使う。見ている局だけ・アプリを閉じて 3 分で止まって消える
- 動かないときの確認: `curl http://<tailscale-ip>:23236/timeshift/<serviceId>/start` を何回か呼んで `seconds` が増えるか

## 中身
- streamd: `/timeshift/{id}/start|info|play?from=|stop`。32MB ごとのファイル、古い分は消す、play は追いついたら新しい分を待って流し続ける
- PlayerEngine: ファイルでない再生でも「流し始めてからの秒」を position に出せるように（`tracksStreamPosition`）
- PlayerView: 5 秒おきに start を呼んで状態を取る。局を替えたら stop。追っかけ中に切れたら 1 回だけその位置で開き直し、駄目ならライブへ

## レビューで直したもの
- streamd: セグメントの大きさを 188 の倍数に（古い分を消したあと、いちばん古い位置から流すと CPU を回し続けて何も送らなかった）
- streamd: play は新しくバッファを作らない。バッファに番号を付け、アプリは番号が変わったら（長く止めていた・録画にチューナーを譲った等）ライブに戻す
- streamd: stop は端末ごと。ほかの端末が同じ局を見ている・追っかけ再生中なら止めない
- streamd: 起動時に前回の残りを消す。バッファごとに別のフォルダ。消す処理と位置の計算が同時に走って落ちることがあったのを修正
- アプリ: 局を替えた直後に前の局の範囲を出さない。streamd に届かない間は操作を出さない
- アプリ: ロック画面で止めていた状態から追っかけに入ったとき、「停止中」の表示が残らないように
