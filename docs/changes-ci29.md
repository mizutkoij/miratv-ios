# ci29: 待ち時間とラジオ・録画の音切れ（2026-10-19）

## 背景（ユーザー報告）
- 録画: 帯域が足りないと音が出なくなる
- ラジオ: 遅い。よくエラーになり、手で再試行すると直る
- 全体: 何かと「接続中」で待たされる。個人用で接続先や局は固定なのだから、毎回読み込まずに前提のまま動いてほしい

## 変更

### 前回の結果をすぐ出して、裏で取り直す（App/Cache.swift）
- `DiskCache`: 取得した生 JSON を Caches/MiraTV/ に保存
  - Mirakurun の局一覧、EPGStation の概要（2 時間ぶん）、番組表（放送波×日）、radio-web の局カタログ、ラジオの番組表、ライブ HLS のプリセット名（UserDefaults）
  - 起動直後はこれを表示し、取り直しに失敗しても前回の内容で続ける（「前回の一覧を表示中」と出す）
  - ラジオの過去の日の番組表は、アーカイブ付きで保存済みなら取り直さない
- `ImageStore` / `CachedImage`: 局ロゴを端末に保存。AsyncImage は毎回取りに行っていた
- 起動時に EPGStation の概要を 2 回取っていたのを 1 回に
- 概要の取得に失敗しても、前回の概要があれば Mirakurun から局ごとに 0.5MB ずつ取り直すフォールバックに入らない

### 一時的な失敗の取り直し（Net.data）
- タイムアウト・接続断・500/502/503/504 は、0.7 秒、1.4 秒あけて最大 2 回送り直す（GET のみ。予約の追加・削除は送り直さない）
- ラジオのアーカイブ play は 1 回だけ送り直す

### ラジオのライブの自動再接続（RadioPlayer）
- 開始の失敗、再生中のエラー、8 秒以上止まったまま、ストリーム終端 → 1, 2, 3, 4 秒あけて最大 4 回つなぎ直す
- 再生に入ったら回数を 0 に戻す。ログに `[radio] ライブ再接続 n/4`

### 録画の音切れ（PlayerEngine）
- データ切れの判定を「映像と音声の大きい方」から「遅い方」に変更。
  以前は音声だけ先に尽きても時計が進み続け、遅れて届いた音声が過去扱いで捨てられて無音になっていた
- データ切れで時計を止めている間は、読み込みを待たせない（遅い方が貯まらず再開できなくなるのを防ぐ）
- 映像サンプルの末尾時刻の計算で duration（invalid）を足して NaN になっていたのを修正

### 受信の先読み（TSPipeline）
- `async:` プロトコル（FFmpeg 内蔵、4MB の先読みスレッド）で開く。開けないビルドなら通常の http で開き直す（ログに出る）
- `TSPipeline.useReadAhead = false` で無効化できる

### 録画の開始（RecordedPlayerView）
- 直接配信（/raw）が使えるかの HEAD 確認（最大 4 秒）をやめ、使える前提で開く。再生に入る前に失敗したときだけ EPGStation に切り替える
- 「もう一度」は今のソースで開き直し、元の位置に戻る

### レビュー後の修正
- 保存した概要が 2 時間より古ければ「持っていない」扱い（EPGStation が落ちているときに Mirakurun のフォールバックが働くように）
- ラジオの過去日の番組表: 放送日（05:00 区切り）で判定し、保存から 6 時間以内のときだけ取り直しを省く
- ライブの再接続: 一時停止中はつなぎ直さない／1 回の失敗で 2 回分数えない
- async: が使えるかは起動後 1 回だけ判定し、開けなかったときの http での開き直しはしない（待ち時間が 2 倍になるため）
- Mirakurun の接続先を変えたら、前のサーバーの一覧を残さない
- 音声が 3 秒以上届いていないときは、映像だけでデータ切れを判定（音声が消えたまま時計が止まり続けないように）
- アーカイブ play はタイムアウトでは送り直さない（最大 6 分待ちを防ぐ）
- 10 日より古い保存分は起動時に消す

## 実機で見てほしいこと

- ログの `先読み(async:) 使用` / `不使用` のどちらが出るか
- ラジオのライブで `ライブ再接続` が出た後に鳴り出すか
