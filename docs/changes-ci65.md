# ci65: アーカイブの mp4 も自前の画面で（全画面・写真・録画・PiP）（2026-10-21）

アーカイブの mp4（配信サービス由来の録画）は iOS 標準の再生画面（AVPlayerViewController）をそのまま出していたので、
TS と違って横の全画面・写真・録画が使えなかった。再生は AVPlayer のまま、画面と操作を TS と同じ自前のものにした。

## 変わったこと
- mp4 も縦 / 横（全画面）を回転と「全画面」ボタンで切り替え。横はタップで操作を出し入れ（TS と同じ）
- シークバー・±15/30 秒・速度・一時停止・ミニプレイヤーは TS と同じ部品
- 写真: いま映っている 1 枚を保存（AVPlayerItemVideoOutput。一時停止中で取れないときはファイルからその位置の 1 枚）
- 録画: 押した位置からもう一度押した位置まで（最大 5 分）を、元のファイルから切り出して写真に保存
  - mp4 は H.264 / HEVC のままなので作り直さない（画質そのまま・速い）。写真が受け付けなければ作り直して保存
  - 背面に回っても PiP でも続けられる（TS の録画は 1 枚ずつエンコードするので背面で止まる）
  - 保存のときに nzb-dl から区間を読み直すので、長いほど時間がかかる（5 分で 300MB 前後）
  - 録画中にシークすると取り消す（TS も同じ）
- PiP: AVPlayerLayer の PiP（ボタンと、ホームに戻ったときの自動）
- TS のアーカイブにも「録画」を付けた（録画の再生画面と同じ ClipRecorder）
- 音声だけのファイルは映像の場所に「音声のみ」。写真・録画・PiP は無効

## ファイル
- `MiraTV/Player/AVFilePlayback.swift`（新）: AVPlayer の再生・状態・写真・区間の切り出し・PiP、`AVLayerSurface`
- `MiraTV/UI/UsenetPlayerView.swift`: TS と mp4 で同じ画面。操作は mode で TSPipeline / AVFilePlayback に振り分け。標準の再生画面（mp4Layout）は削除

## 実機で見るところ
- 横にしたとき・「全画面」で、mp4 が横いっぱいになるか
- 録画の保存（AVAssetExportSession が nzb-dl の URL から区間を切り出せるか。失敗したらデバッグログの `[clip]`）
- 写真が黒くならないか（DRM は無いはずだが、HDR の配信由来の映像だと色が変わるかもしれない）
- PiP の開始・終了、ミニプレイヤーとの行き来で映像が消えないか（AVPlayerLayer の付け替え）
