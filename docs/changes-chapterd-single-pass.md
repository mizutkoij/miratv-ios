# ci51: CM 検出・字幕の取り出しを速く（2026-10-19）

サーバー（chapterd）だけの変更。アプリはそのまま（表示の番号だけ ci51）。

## 何が変わったか
- **1 回の読み込みで両方作る**: これまでは CM 検出（ffmpeg）と字幕の取り出しで、録画ファイルを別々に 2 回読んでいた。いまは 1 回読みながら同時に作る。片方だけ頼まれても、もう片方も作っておく
- **ffmpeg に映像を渡さない**: 録画から PAT・PMT・主音声のパケットだけ（録画の 2% ほど）を抜き出して ffmpeg に流す。ffmpeg が数 GB の TS を読み解く手間が無くなる
- **パケットの探し方を速く**: 各パケットの PID の列だけを抜き出して探すので、Python の処理が約 8 倍速い（156MB を 0.2 秒）
- **録り終わったら先に作っておく**: chapterd が 5 分おきに EPGStation の新しい録画（最新 24 本）を見て、まだのものの CM と字幕を作っておく。アプリで開いたときには出来ている
  - 録り終わって 2 分たってから。ほかの作業が並んでいるときは待つ。1 本ずつ、IO は今までどおり idle 優先度
  - `EPGSTATION_URL` を空にすると、今までどおり開いたときだけ

## 目安（1 時間の番組、約 7GB）
- これまで: CM 約 1〜1.5 分 ＋ 字幕でもう 1 回読む（合わせてディスクを 2 回読む）
- これから: ディスクを 1 回読むだけ（多くの HDD で 1 分弱）。CPU は ffmpeg が音声だけをデコードする分と、約 10 秒の Python
- 先に作っておく分は、開いたときの待ち時間 0

## 結果は同じ
- 合成した録画（無音が 15 秒おき）で、これまでの方式と無音の位置・CM の区間が一致することを確認
- CM の時刻は「映像・音声のうち早いほうの最初」が 0（これまでと同じ基準）になるように、音声の始まりとの差を足している
- 作った CM・字幕は今までのキャッシュと同じ形式。前に作った分はそのまま使える

## 入れ方（homeserver）
- `server/chapterd.py`・`server/arib_caption.py` を入れ替え、`server/miratv-chapterd.service` の `EPGSTATION_URL` を確認して `systemctl --user daemon-reload && systemctl --user restart miratv-chapterd`
- ログに `scan done <id> 52s cm blocks: 6 caption lines: 812` のように、かかった時間が出る

## レビューで直したもの
- CM 側（ffmpeg）が失敗すると字幕の結果まで捨てていた → 字幕は保存し、CM だけ「失敗」に。音声の無い録画では ffmpeg を起動しない
- 失敗した録画を、先に作る処理が 5 分おきに読み直していた → 同じ大きさのファイルは読み直さない（大きさが変わるか、再起動で再挑戦）。アプリから開いても読み直さず失敗を返す
- 途中で 1 バイト欠けた・増えた録画で、そこから先の CM と字幕が全部消えていた → 次の同期位置を探して続ける（合成した壊れた録画で、無音 7 か所すべて検出を確認）
- 録画中のファイルで、CM の結果が「解析中」のまま止まることがあった。ファイルが消された・保存に失敗したときも止まったままだった → どこで失敗しても「失敗」にする
- EPGStation の返す録画におかしな項目があると、先に作る処理が止まっていた → その項目だけ飛ばす
- 先に作る分の後ろで、アプリから開いた録画が待たされていた → アプリからの要求は列の先頭に。先に作る分は、何も走っていないときに 1 本ずつ
- CM 側から作った字幕に録画 ID が入らず、検索結果から開けないことがあった → アプリが字幕を開いたときに埋める
